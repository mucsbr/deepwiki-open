# 部分索引与失败重试

索引状态与可用性分开记录：

- `indexed`：本次纳入索引的片段都有有效向量。
- `partial`：部分片段失败，但成功片段可检索，Ask 允许选择该仓库。
- `error`：本次没有可发布的有效向量，或代码拉取、版本校验等阶段失败。

管理页显示 `indexed_chunks / total_chunks`、失败数、失败文件和错误类别。
页面最多列出 100 个失败明细；索引文件保留全部失败片段。
Ask 的 `search_index` 返回覆盖率和失败信息，缺少搜索结果不能证明代码不存在。
这些数字只针对符合既有文件过滤规则的片段，不代表所有文件都已纳入索引。

普通 **Reindex** 会更新代码，并复用相同模型、维度、源码版本及内容的成功
片段，只为缺失片段重新生成向量。模型或源码版本改变时不混用旧向量。
管理接口可显式传入 `?force=true` 请求重新生成；失败时仍可保留同版本同内容
的有效向量。单纯读取已有部分索引不会触发重试。

写入采用临时文件加原子替换。同一仓库的索引写入串行执行；没有有效向量或
生成期间源码版本改变时，不覆盖原索引。旧文件存在不代表它与当前模型兼容。

分片前会移除 data URI 中内嵌的 Base64 二进制内容，并保留替代标记。
现有分片器之后增加长度保护：默认最多 6,000 字符、2,048 个 `cl100k_base`
估算 token；可在当前 embedder 配置中设置 `max_chunk_chars` 和
`max_chunk_tokens`。该估算不等同于所有模型的 tokenizer。
HTTP 400/422 批次会拆分以隔离坏片段；限流、超时及服务故障不会递归拆批。

代码索引在遍历前剪枝安装依赖目录，包括 Go/PHP/Ruby 的 `vendor`、JS 的
`node_modules`、Python 虚拟环境和 `site-packages`、Java 构建缓存、iOS 的
`Pods`/Carthage、Flutter/Dart 缓存及 NuGet/Cargo 缓存。显式 inclusion 范围
内的嵌套依赖目录也跳过；普通 `packages`、`libs`、`third_party` 源码目录保留。
该规则只影响向量索引，不删除仓库文件，也不限制 Agent 直接读取依赖源码。
索引保存过滤规则签名，Reindex 不会误用过滤规则更新前的完整缓存；模型和
代码版本兼容的自有代码片段仍可复用向量，已排除的依赖不会留在新索引中。

新增索引不序列化 provider 客户端或请求参数，日志不记录完整 embedding
输入。历史日志不自动删除。旧的 `error` 记录无法凭空恢复错误详情；下一次
Reindex 会保存新的诊断信息。
